# 뷰 규약

## 0. 이 문서가 다루는 것

원본 MD가 [[SYNC-STD-001]] 규약대로 쓰여 있을 때, 싱크독 웹의 **유저용 탭**(UI-5 요소 7)이 타입마다 어떻게 그리는지. 읽는 사람은 화면을 만드는 사람이다. 에이전트는 이 문서를 볼 필요가 없다 — 원본만 규약대로 쓰면 뷰는 자동이다.

**원칙**
- 뷰는 원본에서 파생된다. 뷰에 나오는 정보는 전부 원본 또는 DB(참조·플래그·상태)에 있다. 뷰를 위해 원본에 뭔가 더 쓰지 않는다
- 타입마다 다르게 그린다. 유스케이스와 시퀀스가 같은 모양일 이유가 없다. 다만 **어떻게 다른지를 여기 적어** 그때마다 달라지지 않게 한다
- 공통 틀은 최소로. 타이틀 블록과 각주뿐

**이 문서를 쓰기 전에 만든 뷰 셋**(유스케이스·와이어프레임·시퀀스)이 사실상 초안이다. 거기서 잘 된 것을 규약으로 올리고, 제각각이던 것을 맞춘다.

## 1. 공통 틀 — 확정 (PRD 뷰로 검증)

모든 타입이 이 안에 들어간다. `_tools/view_build.py`의 `shell()`이 구현이다. **뷰는 파일 하나** — CSS·스크립트를 내장하고 외부 파일을 참조하지 않는다. 사람이 파일 하나만 열면 된다.

```
┌ 타이틀 블록 ───────────────────────────────────────────────┐
│ 싱크독 · N단계 TYPE                    │ 문서   SYNC-PRD-001 │
│ 제목 (frontmatter.title)               │ 상태   [뱃지]        │
│ 한 줄 설명 (0장 첫 문단)               │ 상위   링크 · 링크    │
│                                        │ 하위   링크 · 링크    │
│                                        │ 항목   N개           │
├ 본문 (타입별, 2장) ─────────────────────────────────────────┤
├ 각주 ──────────────────────────────────────────────────────┤
│ "이 화면은 {파일}에서 생성된 사람용 뷰(STD-002)다. 고치려면 원본을." │
└────────────────────────────────────────────────────────────┘
```

| 부분 | 어디서 오나 | 확정 사항 |
|---|---|---|
| 킥커 | `type` → 단계 번호. STD면 "단계 밖" | 프로젝트 이름 링크는 `index.html` |
| 제목·문서 ID·상태 | frontmatter | 상태는 색 뱃지 (초안 회색·검토중 노랑·승인 초록) |
| 한 줄 설명 | 본문 `## 0.` 절의 첫 문단 | 0장이 없으면 비움 |
| 상위 | frontmatter `upstream` | 문서 뷰로 링크 |
| **하위** | **계산.** 다른 문서 전부의 `[[ ]]`와 `upstream`을 훑어 이 문서를 가리키는 것 | 원본에 없다. 링크에 마우스 올리면 어느 항목을 참조하는지 |
| 항목 수 | 항목 헤딩 수 | |
| 각주 | 고정 문구 + 원본 파일명 | |

**공통 렌더링** — 타입과 무관하게 항상:
- 항목 헤딩 → `#### R12 제목` → 노란 **ID 뱃지** + 제목. `id="item-R12"`로 앵커
- `[[SYNC-X-001#Y]]` → `view_SYNC-X-001.html#item-Y`로 가는 **점선 링크**. 같은 문서 축약 `[[#Y]]`는 `#Y`로 표시. 대상이 없으면 회색 + `?`
- 인라인 코드·코드블록 안의 `[[ ]]`는 링크로 만들지 않는다 (STD-001 1.4)
- mermaid 코드블록 → 그림. CDN 실패 시 코드로 표시하고 문서는 그대로 보임
- html 코드블록(와이어프레임) → 배치로 렌더링. **넣기 전에 다듬는다** — 아래

**html 코드블록은 문서 본문이 페이지에 임의의 HTML을 넣는 유일한 통로다.** 저장소에 push할 수 있는 사람만 쓸 수 있으니 위협 모델 안이지만, 어디까지 허용하는지는 정해 둔다(#19).

- `<script>`와 `on*=` 이벤트 속성은 **지운다.** 와이어프레임은 그림이지 동작이 아니다
- `href`·`src`의 `javascript:`는 지운다
- `data-el`은 뷰가 `data-wf`로 **바꿔 넣는다.** 그대로 두면 문서 본문에서 나온 것과 화면 자신의 요소를 셀렉터로 구분할 수 없다 — 브라우저로 화면을 확인할 때 `[data-el="6.2"]`가 둘 나온다
- 나머지 태그·속성은 그대로 둔다. 와이어프레임은 배치를 보이는 것이 목적이라 인라인 `style`이 필요하다
- `- [ ]` 체크리스트 → 체크박스 모양. **클릭 안 됨** — 원본이 진실
- 절 헤딩(`## 1. …`)은 밑줄, 소절은 그냥 굵게
- 규약 위반·미완성 배너는 웹(UI-5 요소 4·4a)이 DB에서 붙인다. 정적 뷰에는 없다
- 웹은 문단마다 `data-src`(그 문단 **첫 줄의 원본 텍스트**)를 붙여 달라고 요청한다. 줄 댓글 버튼(UI-5 요소 7.4)이 그걸로 원본 줄을 찾는다. **번호가 아니라 텍스트인 이유**: 타입별 렌더러가 본문을 절·항목 블록으로 여러 번 쪼개 공통 렌더러를 부르므로 블록 안 상대 위치로는 원본 줄 번호를 알 수 없다. 정적 뷰는 요청하지 않아 HTML이 지금과 같다 — 거기엔 댓글이 없다

## 2. 타입별 본문

각 타입의 본문을 어떻게 재배치하는지. **"표로 재조립"**은 원본에서 헤딩 항목으로 쓴 것을 뷰가 한눈에 보게 표로 모으는 것 — 원본 규약이 표 행 항목을 금지했으니 그 편의를 뷰가 돌려준다.

### V-RFQ — 확정

원본 순서 그대로. `Q\d+` 항목 헤딩에 뱃지. 재배치 없음 — 인터뷰 기록이라 순서가 뜻이다.

**추적표**는 PRD와 방향이 반대다 — 요구 `Q`마다 "어느 문서가 이 요구를 근거로 삼았나". RFQ는 모든 것의 출발점이라 이 방향이 값어치 있다. 근거로 쓰이지 않은 요구가 있으면 빨간 경고 — 구현 계획이 없다는 뜻.

### V-PRD — 확정

| 절 | 뷰 |
|---|---|
| 목표 | `G` 항목 헤딩들을 **표로 재조립** — 열: `#` · 목표 · 하위 참조 수. 행에 `item-G1` 앵커 |
| 요구사항 | 소절(`### 3.1`) 제목은 그대로. `R`·`N` 항목마다 **카드** — 머리: ID 뱃지 · 제목 · `인수기준 완료/전체` 필 · `하위 N` 필. 몸: 설명 문단(근거 링크 포함) · 인수기준 체크리스트(클릭 불가). 바닥: "이 요구사항을 근거로 삼은 문서" 링크 줄(계산) |
| 비목표·성공지표·ID 체계·미결 | 원본 순서 그대로 |
| **추적표** | 뷰 끝. 이 문서를 참조하는 문서마다 한 행 — 문서 · 제목 · 참조한 항목 목록. 원본에 없고 참조에서 계산 |

카드 13개가 세로로 길다. 접기는 두지 않는다 — 검토는 다 읽는 것이다.

### V-SCN — 확정

| 절 | 뷰 |
|---|---|
| 페르소나 | `P` 항목을 **카드 나란히**(그리드). 역할·겪는 문제·원하는 것 |
| 시나리오 | `S` 항목마다 **카드**. 머리: ID·제목·`N단계` 필. 몸: 주체·상황 → 번호 흐름을 **타임라인**(번호 원 + 세로선) → **변형은 접힘**(펼쳐야 보임) → 성공 조건·연관 요구사항 |
| 대응표 | 원본 표 그대로. 참조는 링크 |

원본 규약이 요구한 블록 구조(주체·상황 / 번호 흐름 / 변형 / 성공 조건 / 연관)를 뷰가 그대로 가른다. 구조를 안 지킨 시나리오는 뷰에서 깨진다 — 규약이 파싱 근거다.

### V-UC — 확정

작업 순서(액터 식별 → 유스케이스 발견·명세 → 패키지)가 위에서 아래로 흐른다.

| 절 | 뷰 |
|---|---|
| 1 액터 식별 | 원본 1장 표 그대로 |
| 2 유스케이스 발견·명세 | **좌** 액터별 항목 목록(`UC-A` `UC-H` `UC-G` `UC-S`) / **우** 선택한 항목 — Cockburn 12행 표 + 기본 흐름 번호 목록 + 확장(분기 번호 강조) + 사후조건·연관. 흐름 안 `UC-xx`는 클릭 이동, `[[ ]]`는 다른 문서 뷰로 |
| 3 패키지 | **탭** — 항목 표의 `패키지` 값으로 묶음. 탭마다 UML 유스케이스 다이어그램(액터·타원·include·extend·일반화). 다이어그램은 원본에 없고 항목 표의 `주 액터`·`포함`·`확장점`·`일반화`에서 그린다. 타원 클릭 → 2로 스크롤 |
| 4 대응표 | 시나리오·요구사항 둘. 원본 그대로, 칩 클릭 이동 |

### V-INFRA

| 절 | 뷰 |
|---|---|
| 제약 | `C` 항목 **표로 재조립**. ID · 내용 · 출처 |
| 구성도·시퀀스 | mermaid 렌더 |
| 나머지 | 원본 순서 |

### V-DOM (문서 셋)

**도메인 모델**: 개념 항목을 카드로. 카드에 속성 목록. `개념 모델` 절의 mermaid는 그대로. 경계 절은 묶음별 카드 묶음.

**클래스 명세**: 2장(엔티티)은 클래스마다 헤딩 + 작은 다이어그램이므로 뷰가 **묶음별로 합쳐 큰 다이어그램 하나**를 만든다. 4장(설계)은 서비스마다 헤딩이고 다이어그램 안에 엔티티 속성이 이미 있으므로 그대로 렌더링. 의존 관계 절의 flowchart는 그대로. 클래스 항목을 클릭하면 메서드 표 + 규칙.

**ERD·DD**: ERD 절의 mermaid 그대로. 테이블 항목마다 DD 표. 테이블 클릭 → ERD 그림에서 강조 (되면).

### V-UI (문서 셋)

**화면 설계**: `UI` 항목 **표로 재조립** (ID·이름·종류·목적·유스케이스). 흐름도 mermaid 그대로. 진입·이탈 표 그대로.

**와이어프레임** (이미 만든 뷰를 규약으로): 상단 화면 탭. 탭마다 **좌 배치 뼈대 / 우 요소 표·규칙·시나리오**. 요소 번호로 양쪽 연동 강조. 뼈대 HTML의 `data-el`과 요소 표의 `#` 열이 같은 번호.

### V-API (문서 둘)

**REST**: 엔드포인트 항목을 **경로별로 묶어 표로 재조립** (메서드·경로·요약·화면·유스케이스). 항목 클릭 → yaml 조각 구문 강조 + 요청·응답 스키마. 뷰가 조각들을 모아 **OpenAPI 전체 문서**를 만들어 내려받기 제공 — 원본 규약 1.5가 조각으로 쪼개라고 한 것을 뷰가 합친다.

**MCP**: 도구 항목 카드. inputSchema를 표로(필드·타입·필수·설명). 결과 예시·에러 표. `에이전트 순서` 절은 그대로.

### V-SEQ (이미 만든 뷰를 규약으로)

| 부분 | 뷰 |
|---|---|
| 좌 | 시퀀스 목록. **의미 묶음**으로 — 묶음은 원본 대응표의 순서가 아니라 뷰 규약이 정한 그룹(저장 파이프라인·판단·조회·운영·공통) |
| 본문 위 | **생명선 표** — 원본 `생명선` 절에서 이 시퀀스에 등장하는 것만 골라 |
| 본문 가운데 | 좌 mermaid 렌더(확대 버튼) / 우 **단계 목록** — mermaid 화살표에서 자동 추출. 번호·누가→누구·무엇. alt/opt/loop 문맥을 회색 줄로 |
| 본문 아래 | 읽을 때 볼 것 |

### V-MS

함수 항목마다 카드. 시그니처 코드 + 처리 단계 번호 목록 + 예외 표. 함수 목록 절을 **서비스별로 묶어 표로 재조립**.

### V-CODE

커밋·PR 링크 목록. 각 링크가 참조하는 MINISPEC 항목을 옆에.

### V-STD

원본 순서 그대로. 규칙 항목 헤딩에 뱃지. 표준 문서는 프로젝트 상세에서 11칸 밖 "표준" 묶음으로 진입한다.

## 3. 뷰가 원본에 없는 것을 만드는 곳

원칙 위반이 아닌지 확인하려고 모아둔다. 전부 **원본 또는 DB에서 계산**된다.

| 뷰 | 만드는 것 | 재료 |
|---|---|---|
| 공통 | 타이틀 블록 (상위·항목 수) | frontmatter + 헤딩 |
| 공통 | 타이틀 블록 **하위** | 다른 문서 전부의 참조 |
| V-PRD | 추적표 · 카드 바닥 "근거로 삼은 문서" · 목표 표 하위 수 | 참조 테이블 |
| V-RFQ | 요구별 추적표 · 미사용 요구 경고 | 참조 테이블 |
| V-UC | 유스케이스 다이어그램 | 항목 표의 액터·포함·확장점·일반화 |
| V-DOM 클래스 | 묶음 다이어그램 | 클래스별 다이어그램 조각 합침 |
| V-API REST | OpenAPI 전체 | 엔드포인트 yaml 조각 합침 |
| V-SEQ | 단계 목록 | mermaid 화살표 |
| V-SEQ | 생명선 표 (해당 것만) | 원본 생명선 절 + mermaid participant |
| 여러 곳 | 표로 재조립 | 항목 헤딩 + 블록 첫 줄 |

## 4. 구현

`_tools/view_build.py` 하나가 전부 만든다. frontmatter `type`을 보고 `V-*` 함수로 본문을 그리고, `shell()`이 공통 틀을 씌운다. 타입마다 함수 하나. 출력은 `view_{doc_id}.html` — 파일 하나에 CSS·스크립트 내장. 이 스크립트가 React 유저용 탭의 **참조 구현**이다 — React는 이 HTML과 같게 그려야 한다.

확정된 것: 공통 틀과 12타입 전부. `view_build.py --all`이 문서 25개 + `index.html`을 만든다. 스콥을 줄여 **재배치·재조립·그림 렌더·참조 링크·추적표**까지로 했다 — 아래 6장 참조. 나머지 타입은 하나씩 만들어 보고 확정한다.

## 5. 이미 만든 뷰 셋과의 차이

| 뷰 | 지금 | 규약 | 고칠 것 |
|---|---|---|---|
| 유스케이스 | 패키지 탭 + 좌우 + 추적표 | V-UC 그대로 | 타이틀 블록을 frontmatter에서. 그 외 없음 |
| 와이어프레임 | 화면 탭 + 좌우 | V-UI 그대로 | 타이틀 블록 |
| 시퀀스 | 좌 목록 + 생명선 + 그림/단계 | V-SEQ 그대로 | 타이틀 블록. 좌 목록 묶음 이름을 규약에 적은 것으로 |

셋 다 규약 초안 역할을 했으니 거의 그대로다. 나머지 8타입 뷰는 아직 없고, 이 문서대로 만든다.

## 6. 미결사항 — v2로 미룬 가시성 강화

검토 중 나온 요구를 스콥 밖으로 뺐다. 지금 뷰는 "원본을 사람이 읽기 좋게 재배치"까지다.

- [x] **읽기 층** — 기본은 한눈에(요약 패널 + 수치) → 항목 요약 표 → 전문은 접힘. 지금은 전문이 바로 다 펼쳐진다 — v2 (이 절 제목이 이미 v2로 미룬 것들이다)
- [x] **구조 그래프 자동 생성** — 타입별: PRD 목표→요구→하위 문서, INFRA 제약→구성요소, SCN 페르소나→시나리오→유스케이스. 참조 테이블에서 그릴 수 있다 — v2 (이 절 제목이 이미 v2로 미룬 것들이다)
- [x] **항목 한 줄 요약** — 정적으로는 불가. (a) 규약에 "항목 블록 첫 문장 = 한 줄 요약" 추가 (b) 저장 시 LLM 요약 생성(PRD 신규 기능). 둘 다 미결 — v2 (이 절 제목이 이미 v2로 미룬 것들이다)
- [x] 수치 압축 — 인수기준 완료율, 근거 없는 항목, 하위 없는 항목 등 커버리지 — v2 (이 절 제목이 이미 v2로 미룬 것들이다)

- [x] V-DOM 클래스에서 조각을 합친 다이어그램의 레이아웃 — mermaid가 자동 배치하므로 원본 순서와 다를 수 있다 — 결정: mermaid 자동 배치에 맡긴다. 실제로 렌더해 보니 묶음이 최대 네 클래스(2.2 명세)라 순서가 바뀌어도 한눈에 다 보인다. 관계선 알파벳 정렬도 유지한다 — 원본에서 관계 서술 순서를 바꿔도 뷰 결과가 흔들리지 않는다
